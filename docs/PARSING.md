# Как подобряваме парсването (PDF и готови packing листове)

Идеята: всеки нов или проблемен файл става **случай** в корпуса. Подобряваме парсера на модула, а корпусът показва
веднага дали резултатът за ВСИЧКИ досегашни файлове е останал същият (или се е подобрил там, където искаме).

## 1. Когато файл не се чете както трябва
1. В програмата отворете плочката **Анализ** и пуснете файла.
   * PDF: „Текст по колони“, „Редове (с позиции)“, „Думи“ (с координати) и „Страница с рамки“. Ако PDF-ът е сканиран,
     OCR се пуска автоматично (или принудително от падащото меню). Така се вижда какво реално вижда парсерът.
   * Excel/CSV: всички листове, обединени клетки и **вероятни заглавни редове** (подсветени).
2. **Запази пакет за анализ** - създава ZIP (оригиналният файл + анализът) в `Документи\Logistics Packing\Анализ\`.
   Изпратете ZIP-а - от него се прави тест случай и се коригира парсерът.

## 2. Корпус и регресионна проверка (за разработка)
Корпусът е в `tests/corpus` (извън git - съдържа клиентски данни; друга папка: `LPS_CORPUS=...`).

```bash
node tools/corpus.mjs add dior "C:\...\OA 1264457.pdf" "C:\...\COMMESSA.pdf" --name blue-1264457
node tools/corpus.mjs update dior/blue-1264457   # записва "златен снимък" на резултата (проверете го първо!)
node tools/corpus.mjs run                         # сравнява всички случаи със снимките; код 1 при разлика
```
* Случаят е папка с входните файлове + `case.json` (`files`, `preview` - селектор на прегледа/етикетите,
  по желание `pre`/`post` - кликове преди/след качването, напр. за избор на раздел или бутон „Генерирай“).
* Снимката е текстът на прегледа/етикетите след зареждането. Промяна в парсера, която променя резултат, се вижда като
  `-` (беше) / `+` (стана). Ако промяната е желана - `update`.
* Python модулите (ACNE, ASPHALTE, COURREGES) се стартират автоматично от корпуса.

## 3. Общият engine (OCR/PDF)
`runtime/lps_engine` - единен слой за PDF текст с координати (PyMuPDF) и OCR (Tesseract). HTML модулите го викат с
`LPS.engine.pdfText(file)`; Python модулите - `import lps_engine`. Нови/подобрени PDF парсери трябва да се правят върху него,
за да ползват един и същ OCR и един и същ начин на подреждане на думите в редове и колони (`lps_engine.lab.group_lines`).

## 4. Проверки
```bash
python -m unittest discover -s tests/engine      # engine + лаборатория
node tools/test_lab_ui.mjs                        # страницата на анализа
node tools/test_engine_bridge.mjs                 # мост LPS.engine <-> engine
node tools/corpus.mjs run                         # регресия върху реалните файлове
```
